## 1. 建设目标

建设一个在电脑浏览器中全屏展示的前端可视化页面，用一个轻量、写实的三维模型帮助用户理解磷石膏堆场从基坑到植物修复的变化过程。页面同时展示报告中确实存在的场地信息和检测数据。

系统展示两个场地：

- 湖北楚星化工股份有限公司三板湖磷石膏库，页面简称“三板湖”。
- 宜昌中孚化工东西泉磷石膏库，页面简称“东西泉”。

两个场地不并排比较。用户一次只查看一个场地；每个场地的页面中央都是该场地当前阶段的三维示意模型，四周展示该场地的数据。

## 2. 范围与边界

### 2.1 本次实现

- 单页前端界面，无登录、后台和数据库。
- 适配电脑浏览器全屏显示，优先保证 16:9、1920×1080 分辨率。
- 三板湖与东西泉场地切换。
- 五个修复阶段切换。
- 中央三维模型支持鼠标拖动旋转和滚轮缩放。
- 场地或阶段切换后，三维模型和周边数据同步变化。
- 页面数值来自指定报告，缺失数据统一显示“暂无数据”。
- 数据条目显示单位、样品名称和来源文件。

### 2.2 本次不实现

- 不还原两个场地的真实地形、真实尺寸和工程图纸。
- 不制作人员漫游、第一人称行走、车辆施工动画或复杂粒子效果。
- 不建立后台管理系统，不提供页面内的数据编辑或上传功能。
- 不接入实时监测设备、地图服务或外部接口。
- 不估算、不插值、不编造报告未提供的数据。
- 不把两个场地放在同一画面中进行排名或对比。

## 3. 五阶段定义

五个阶段保持固定，不因场地切换而改变：

1. 原始基坑
2. 基坑整理与防渗
3. 磷石膏堆填
4. 封场覆土
5. 植物修复

这五个阶段用于说明一般工程过程，不表示报告对两个场地都保存了五个历史阶段的完整实测记录。

## 4. 页面结构

页面采用深蓝色科技监测界面，中央模型区域使用自然、写实的环境色彩。整体分为五个区域：

### 4.1 顶部标题栏

- 显示项目标题“磷石膏堆场生态修复三维可视化平台”。
- 提供“三板湖”和“东西泉”两个场地按钮。
- 当前场地按钮有明显高亮状态。
- 切换场地时保留当前阶段。例如用户在“封场覆土”阶段从东西泉切换到三板湖，切换后仍显示三板湖的“封场覆土”阶段。

### 4.2 左侧基础信息栏

展示不随阶段切换的场地基本信息，包括：

- 场地名称
- 地理位置
- 设计或记录库容
- 磷石膏来源类型
- 投运时间
- 封场或运行状态
- 与长江支流的距离

### 4.3 中央三维模型区

- 占据页面最大的可视面积。
- 显示当前场地、当前阶段的写实示意模型。
- 左下角显示操作提示：“拖动旋转 · 滚轮缩放”。
- 角落显示“示意模型，非真实地形复原”，避免用户误解。
- 模型切换采用短暂平滑过渡，不播放冗长动画。

### 4.4 右侧阶段数据栏

- 显示当前阶段可以确认归属的检测数据或工程信息。
- 检测数据较多时，使用简单的样品标签切换，例如“磷石膏样品1”“渗滤液样品1”，避免页面出现很长的滚动表格。
- 每个数字包含指标名称、数值和单位。
- 数据区底部显示样品名称及来源报告。
- 当前阶段没有明确数据时，显示灰色“暂无数据”，同时保留阶段说明。

### 4.5 底部阶段栏

- 五个阶段按工程顺序横向排列。
- 当前阶段使用高亮色和较大的文字。
- 点击阶段后同时更新模型、阶段说明和右侧数据。
- 不自动轮播，避免用户正在阅读时页面自行变化。

## 5. 三维模型设计

### 5.1 总体风格

采用“轻量写实”风格：材质、颜色、光照和阴影接近真实环境，但不追求照片级建模。两个场地共用同一套基础模型，以降低复杂度；场地差异主要通过页面名称和数据体现。

### 5.2 阶段视觉变化

| 阶段 | 三维画面 |
| --- | --- |
| 原始基坑 | 裸露土石、自然边坡、凹陷基坑和少量周边植被 |
| 基坑整理与防渗 | 整理后的坡面、黑色防渗膜和简化排水结构 |
| 磷石膏堆填 | 白灰色磷石膏堆体，形成分层或台阶状堆坡 |
| 封场覆土 | 堆体整形后覆盖棕色土层，局部保留施工后的裸土质感 |
| 植物修复 | 覆土坡面形成草本覆盖，配少量灌木，表现生态恢复状态 |

模型保持相同观察角度和场地边界，使用户能直观看出阶段之间的变化。通过显示、隐藏和调整模型分层实现切换，不为每个阶段下载一套大型模型。

### 5.3 交互和性能

- 鼠标左键拖动：环绕旋转模型。
- 鼠标滚轮：缩放。
- 限制相机俯仰角和缩放范围，避免视角进入地下或离模型过远。
- 不开放平移和第一人称移动。
- 对植物、石料等重复物体采用轻量绘制方式。
- 限制高分辨率屏幕的渲染倍率，保证普通电脑运行流畅。

## 6. 数据规则

### 6.1 数据来源优先级

1. 场地基础信息优先使用《磷石膏资源环境数据库最终版0612》。
2. 生态修复示范工程信息使用《课题结题报告-0614》。
3. 《调研报告-磷矿区生态修复-6.9》和《磷石膏综合利用技术工艺包0610》用于补充背景和工艺理解，不把其中其他企业或其他地区案例的数据移植到两个目标场地。
4. 云天化矿坑内容只属于外部案例，不作为三板湖或东西泉的场地数据。

### 6.2 报告差异处理

- 东西泉库容在不同报告中存在差异。页面基础信息采用数据库最终版记录的 335 万 m³。
- 结题报告中约 415×10⁴ m³、约 0.21 km²和约315亩的描述不与数据库数值混合计算。
- 场地与长江支流距离采用数据库表格值：三板湖 1.16 km，东西泉 17～17.35 km。
- 若后续需要展示存在差异的另一数值，必须在页面上明确标注具体来源，不把两个口径合并为一个结论。

### 6.3 缺失值处理

数据文件用空值表示报告没有提供该阶段的明确数据。界面收到空值后统一显示“暂无数据”。禁止使用 0 代替缺失值，因为 0 会被误解为实际测量结果。

### 6.4 数值展示原则

- 原样保存报告中的数值和单位。
- 不计算平均值来替代原始样品。
- 不用颜色宣称“达标”或“超标”，除非报告明确提供适用标准和判定结果。
- 样品指标只能显示在能够确认归属的场地和阶段中。
- 项目通用试验目标不冒充场地实测数据。

## 8. 前端技术方案

采用 Vite、原生 JavaScript 和 Three.js：

- Vite：负责在本地启动页面并生成可发布文件，可以理解为轻量的前端开发和打包工具。
- 原生 JavaScript：负责按钮、数据和页面状态，不引入额外界面框架。
- Three.js：负责在浏览器中绘制三维模型。

不采用复杂前端框架，目的是减少文件数量和学习负担。

## 10. 状态与更新流程

页面只维护两个核心状态：

- `currentSite`：当前场地。
- `currentStage`：当前阶段。

用户点击场地或阶段后，程序按以下顺序更新：

1. 保存新的场地或阶段。
2. 更新按钮高亮状态。
3. 从 `siteData.js` 读取对应数据。
4. 更新左侧场地信息和右侧阶段信息。
5. 调用三维场景模块更新模型。

三维场景只初始化一次，切换时复用现有模型和渲染器，避免反复创建场景导致卡顿。

## 11. 异常处理

- 报告没有提供的字段显示“暂无数据”。
- 纹理加载失败时退回到纯色材质，三维模型仍可显示。
- 浏览器不支持 WebGL 时，在中央区域显示“当前浏览器无法显示三维模型，请尝试更新浏览器或启用硬件加速”。
- 页面运行中出现数据字段缺失时，隐藏该指标的空图表，不显示 `undefined`、`NaN` 等程序文字。
- 浏览器窗口尺寸变化时自动重新计算三维画布尺寸。

- 两个场地按钮均可用，场地信息随选择正确变化。
- 五个阶段均可进入，阶段名称和顺序正确。

- 模型可旋转和缩放，不能无限缩小、穿入地下或进入漫游模式。

## 13. 完成定义

当页面同时满足以下条件时视为完成：两个场地可切换、五阶段模型变化明确、写实风格达到已确认的参考方向、旋转缩放可用、数据与阶段同步、报告缺失值处理诚实、1920×1080全屏显示清晰，并通过第12节中的检查。
