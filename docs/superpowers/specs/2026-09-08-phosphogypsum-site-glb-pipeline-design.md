# 磷石膏堆场 GLB 精细化管线设计

## 目标

在不改变现有页面布局、数据面板、两个场地切换和五阶段交互的前提下，将中央三维场景升级为更接近真实磷石膏工程堆场的五阶段 GLB 模型。两处场地共用同一套模型，第三张参考图决定主体形态，第一、二张参考图补充工程细节。

## 视觉基准

主体采用宽阔、低矮、灰白色的大型工程堆场形态，不表现为自然山体、棕色土堆或规则圆台。场景尺度继续与现有约 `108 × 90` 的地形范围兼容，堆体最高约 `9–11` 场景单位。

- 使用轻微偏心、非对称的不规则闭合轮廓。
- 设置四级退台，各级平台宽度、中心偏移和边缘扰动不同。
- 顶部平台约占主体投影面积的 30%–40%，整体平缓但包含克制的起伏、压实条带和局部堆料痕迹。
- 主运输道路从坡脚进入，通过两处回头弯连接顶部；局部平台设置环形施工便道。
- 坡面包含纵向浅冲刷纹和横向分层痕迹，但这些细节不能破坏清晰的工程轮廓。
- 磷石膏使用粉灰、冷浅灰和灰白色变化；施工道路使用略深的灰土色。
- 排水沟、坡脚过渡和平台边缘作为低成本独立网格表现。

第三张参考图提供多堆体相连、宽平台、分级边坡和运输网络的主要视觉语言。第一张参考图用于补充浅灰覆盖、压实纹和坡脚设施；第二张参考图用于补充不均匀边界、局部冲刷、道路以及膜面工程痕迹。

## 五阶段资产

Blender 脚本使用固定随机种子和共享轮廓参数生成五个独立 GLB，使阶段之间保持空间连续性。

### pit

生成不规则开挖基坑、粗糙坑底、分级裸露边坡和一条施工下坡道。主色为克制的灰褐岩土色，不抢占后续磷石膏阶段的视觉重心。

### liner

复用基坑结构，在坑底和边坡铺设深灰色防渗膜。膜面包含拼接缝、轻微褶皱暗纹、边缘压覆和简化排水管或排水沟。

### stack

作为核心资产，生成四级退台、宽阔平顶、非同心平台和连接坡脚至顶部的运输道路。坡面加入浅色层理、纵向冲刷和压实变化，主色明确为灰白磷石膏。

### cover

保持 stack 的工程轮廓，以薄层棕灰色覆土覆盖主体，并加入施工碾压条带和车辙。道路、平台和退台结构仍清晰可辨。

### restoration

保持 cover 的轮廓和道路，在其上形成不均匀植被斑块。草地、灌木、少量幼树和裸土区域混合分布，避免均质草坪效果。重复植被优先使用可复用的低面数网格，并限制实例数量。

## Blender 生成架构

新增 `scripts/blender/`，按职责拆分：

- `generate_phosphogypsum_site.py`：命令行入口、随机种子和五阶段编排。
- `terrain_generator.py`：共享不规则轮廓、基坑与四级退台主体网格。
- `materials.py`：本地程序化 PBR 材质，包括颜色、粗糙度和 bump/noise。
- `roads.py`：运输道路、平台便道和压实条带。
- `drainage.py`：排水沟、排水管、膜面拼接与坡脚设施。
- `export_glb.py`：命名校验、网格清理、法线处理和 GLB 导出。

入口脚本支持生成全部阶段或指定阶段。默认输出到 `public/assets/models/`：

- `pit.glb`
- `liner.glb`
- `stack.glb`
- `cover.glb`
- `restoration.glb`

每个文件仅包含该阶段所需主体和附属细节。材质与程序化纹理烘焙或直接嵌入 GLB，不依赖在线资源。导出前合并适合合并的静态网格、删除未使用数据，并保持统一原点、比例和朝向。

## Three.js 加载架构

新增独立的阶段资产加载模块，使用 Three.js 自带的 `GLTFLoader`，不增加 npm 依赖。

- 阶段资源映射集中维护，避免路径散落在场景代码中。
- 加载器按 URL 缓存 Promise 和成功结果，防止重复请求与并发重复解析。
- 页面启动时立即显示现有程序化模型，并在后台预载五个 GLB。
- 当前阶段 GLB 就绪后替换程序化主体；缓存命中时阶段切换立即完成。
- 目标 GLB 尚未就绪或加载失败时，继续显示相同阶段的程序化地形、工程细节和植被。
- 单个资产失败只影响对应阶段。开发环境输出一次明确警告，失败不会向上抛出并破坏渲染循环。
- 快速连续切换使用请求序号或当前阶段校验，过期的异步完成事件不得覆盖最新选择。
- GLB 加载后统一设置阴影、色彩空间相关材质属性和场景缩放。材质缺失时按阶段应用可接受的纯色 PBR fallback。
- 销毁场景时释放 GLB 网格、材质和纹理；缓存模块避免对仍在使用的共享资源重复释放。

现有 `createSiteModel` 继续暴露 `root`、`applyStage`、`update` 和 `dispose`，确保 `createScene` 与 UI 状态接口不变。程序化地形仍是完整的运行时 fallback，而不是仅在开发中保留的死代码。

## 阶段切换行为

程序化 fallback 保留现有高度渐变。GLB 阶段采用短时透明度交叉淡入或直接替换，以实现稳定性为优先；加载期间不显示空场景。两个场地切换不触发模型重新下载，只继续使用共享缓存和当前阶段模型。

## 性能预算

- 单阶段主体与工程细节以约 80k–180k 三角面为目标，上限为 250k。
- 单阶段 GLB 目标大小不超过 12 MB，五阶段总量目标不超过 45 MB。
- 纹理以 1K 为主，只有对主体视觉贡献明确时使用 2K。
- 静态材质和几何尽量合并，单阶段 draw call 目标不超过 40。
- 植被使用低面数重复网格或实例化友好的结构，不生成高密度森林。
- Three.js 像素比、阴影贴图和相机控制保持现有性能边界。

## 测试与验收

自动测试覆盖：

- 五阶段资源路径映射完整且稳定。
- 同一路径只发起一次并发加载并复用缓存。
- 目标资产成功后显示 GLB、隐藏程序化对应层。
- 加载失败时保留程序化阶段，且场景接口仍可继续切换。
- 快速阶段切换不会被较早的异步结果覆盖。
- 销毁过程释放自身资源且不重复释放共享对象。
- 现有状态、阶段配置、地形和 UI 测试继续通过。

实施完成后执行：

1. 使用 `D:\Softwares\Blender\blender.exe` 无界面运行生成脚本。
2. 检查五个 GLB 均存在、文件大小符合预算，并解析验证命名和网格结构。
3. 运行 `npm test`。
4. 运行 `npm run build`。
5. 启动本地页面，在 1920×1080 视口检查两场地和五阶段切换、旋转缩放、加载失败 fallback、视觉层次及控制台错误。

## 非目标

- 不依据航测或 GIS 数据复原某一真实场地的精确地形。
- 不为两个场地生成不同模型。
- 不改变页面信息架构或增加复杂控制 UI。
- 不使用在线材质、外部 CDN 或高面数扫描资产。
- 不移除现有程序化地形管线。
